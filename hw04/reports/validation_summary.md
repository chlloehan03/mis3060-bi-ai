# Part D Validation Summary

Generated by `scripts/03_validate.py`. Raw and clean layers are validated with identical checks.

## Labels

* **Confirmed error** - violating the rule is a definite defect (logical/standard rules, or the decision log calls it a confirmed error). Scored in the business-rule pass rate.
* **Structural** - blank-pattern rules (e.g. cash transactions have no security). A legitimate structural blank PASSES; only a wrong pattern fails. Scored in the business-rule pass rate.
* **Suspicious** - looks wrong or conflicts with other data but is not proven wrong. Reported as suspicious rows, NOT counted as business-rule failures.
* **Informational** - observed patterns and category sets read off the data. Reported only.
* **Basis** - Documented (decision log) / Logical/standard / Observed in data / Assumed threshold. Assumed thresholds: age 18-120, years_experience 0-70, expense ratio <= 1000 bps, return_ytd -0.5..1.0, bps <= 100, $1 fee tolerance, $0.01 AUM tolerance.

## Scorecard denominators

* **completeness_pct** = populated required cells / required cells. Required cells = rows x original business columns minus structural-blank cells (ETF sector, non-ETF expense ratio, security_id/shares/price on cash transactions). Literal `None` in certifications counts as populated. Flag columns are excluded so adding flags cannot raise the score.
* **pk_uniqueness_pct** = distinct non-blank primary keys / rows.
* **type_validity_pct** = non-blank cells that parse as their type / non-blank cells in typed (non-text) columns. Scientific notation is a valid number, so it does not lower type validity.
* **numeric_format_consistency_pct** = numeric cells in plain (non-scientific) notation / numeric cells. This is the only metric the cleaning step was designed to change (Decision 16).
* **business_rule_pass_pct** = passing row-checks / applicable row-checks, over Confirmed-error and Structural rules (row-weighted; each rule contributes its applicable rows).
* **confirmed_error_row_pct** = rows failing at least one Confirmed-error rule / rows. This is row-based, unlike the row-weighted business_rule_pass_pct, so rules that pass on every row cannot dilute it.
* **suspicious_row_pct** = rows failing at least one Suspicious rule / rows.
* **referential_match_pct** = matched non-blank FK values / non-blank FK values across the table's outgoing relationships. Blank security_id on cash transactions is structural and excluded (reported as null-key rate). Tables with no outgoing FK show N/A.
* Flags do not change any score: clean rows that are flagged still fail the same rules as raw.

## Ambiguities and assumptions

* No official Part D instructions file was available; requirements were taken from the assignment prompt.
* R1 compares against all fact_fees rows (as Part A did) and against fee_type = Advisory only, because it is undocumented which fee rows the Advisory Fee transactions represent.
* R2 matches on client_id and month; fee_date and snapshot_date are both the 1st, so exact date equality is used.
* Business-rule pass rate uses only Confirmed-error and Structural rules. Suspicious findings are shown separately so unproven issues do not count as defects.
* In-window oversells (Decision 2) and dividend amounts (Decision 1) are Confirmed errors, so fact_transactions scores below 100% in BOTH layers - flags do not fix them.
* Holiday check covers only Jan 1, Jul 4 and Dec 25 (as in Part A); floating holidays are not tested.
* The fee amount formula (F07) and one-advisor-per-client rules (P17/T19) are inferred from the data and are not scored.
* Future-date checks use the fixed Part A reference date 2026-10-21.
* IQR uses pandas' default linear-interpolation quantiles.
